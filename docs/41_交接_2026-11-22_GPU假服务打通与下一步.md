## 1. 这一轮做成了什么（有真机证据）

真机照片（2026-11-22 17:2x，红米 Note 10 5G / MT6833 / Mali-G57 MC2）上确认：

```
SWEET MALI: v54 compute copy 0/0 words ok
SWEET GPU: service state=1 gpu_id=90930010     ← 假 GPU 服务已发布
SWEET MALI: BG batches=29 jobs=232 ok=29 bad=0  ← GPU 后台任务正常
```

含义：
- 内核里 **`IOAcceleratorES` 服务已创建并 `registerService()`**，属性为：
  `MetalPluginName = SweetMTLDriver`、`MetalPluginClassName = VMDevice`、`IOUserClientClass = SweetGPUUserClient`
- iOS 的 Metal 用 `IOServiceMatching("IOAcceleratorES")` 能枚举到它（这是 iOS 找 GPU 的唯一方式）
- GPU 真实 ID `0x90930010` 可被用户态读到（GET_VERSION / GET_PARAM 接口已实现）
- 用户客户端（IOUserClient）可用：`GET_VERSION`、`GET_PARAM` 两个 selector 已实现并返回真实寄存器值

**还没做的**：Metal 插件 bundle 不存在，所以 Metal 枚举到服务后会尝试加载
`/System/Library/Extensions/SweetMTLDriver.bundle` 而失败 → 实际渲染仍全部由 CPU 完成，
**系统流畅度此刻没有任何提升**（这一点必须对用户说清楚）。

## 4. 下一步：让 Metal 真正"能调用"（4 个部件）

参考实现（已下载到本地）：
- `evidence/research/sources/Nik300__viva-gpu.zip` **同款 G57 的 Metal 驱动（真机跑通）**
- `evidence/research/sources/Nik300__ios-viva.zip` / `tphx37__ios-viva.zip` 内核 GPU 补丁 `0100+`
- `evidence/research/viva_ref/viva_gpu_uapi.h`（内核↔用户态 ABI 全文）
- `evidence/research/viva_ref/0100-viva-gpu-mali.patch`（内核实现，123KB）
- `evidence/research/hakios/`（G52 的 panfrost/Metal 说明与 mesa 构建脚本）
- `evidence/research/heliodarwin/`（MT6789 G57 的 MMK ABI 与文档）

### 4.1 内核 UAPI 补全（1–2 天）
现在只有 `GET_VERSION(0)` / `GET_PARAM(1)`。按 `viva_gpu_uapi.h` 的**编号顺序**往后补（编号永不重排）：
`CREATE_BO(2)` / `MMAP_BO(3)` / `GET_BO_OFFSET(4)` / `GEM_CLOSE(5)` / `SUBMIT(6)` / `WAIT_BO(7)` / `SYNC_BO(15)` …
要点：
- BO 用 16 KiB 页（XNU arm64），GPU VA 由内核从 `[32 MiB, 4 GiB)` 分配
- 提交复用已验证的 **v9 JS1 job 链**（v44 已 4/4 跑通），WAIT 用完成位轮询
- 缓存：全部 cacheable + 每次 job 前后显式 flush/invalidate（viva 明确说明不要运行期改 cache 模式）
- 已知地雷：`pmap_sync_page_attributes_phys` 用 `ppnum_t`（uint32）左移 PAGE_SHIFT 会截断（DRAM 基址 0x100000000；HelioDarwin 同因打了 0196）

### 4.2 Mesa iOS 版（2–3 天）
抄 `evidence/research/hakios/tools_mk-mesa.sh` + `panfrost-darwin.patch` + `redwood-drm`：
Mesa 25/26 + panfrost（Valhall v9）+ 自写 libdrm 替身 → `libvulkan_panfrost.dylib` / libOSMesa。
用我们 macOS CI（Xcode iPhoneOS SDK）交叉编译。

### 4.3 Metal 插件 bundle（3–5 天，最重）
抄 viva 的 `driver/metal/*` + `driver/vmg_*`：
- `VMDevice : _MTLDevice`（`MetalPluginClassName = VMDevice` 必须一致）
- 命令缓冲/编码器/资源/管线的最小集合
- 着色器：AIR → NIR → Panfrost（先把一条路打通即可）
产物：`SweetMTLDriver.bundle/{Info.plist, SweetMTLDriver}`，`NSPrincipalClass = VMDevice`

### 4.4 装进 iOS 并让系统加载（1 天）
- 用内核写文件能力（`vn_open_auth` + `vn_rdwr`，已在 v50 补丁里验证过写文件路径）把 bundle 解包写进 `/System/Library/Extensions/SweetMTLDriver.bundle/`
- Metal 在枚举到 `IOAcceleratorES` 后会自动按 `MetalPluginName` 找该路径并 `NSBundle` 加载，不需要改 iOS 系统
- 首次验证用最小程序（`metal_props` 类）打开设备、打印参数，再谈渲染

**时间预期**：Metal 认到设备 3–5 天；第一帧（清屏/三角形）+1 周；桌面 UI 由 GPU 渲染再 +2–3 周。
**性能预期（同款 G57 实测，viva）**：桌面滑动 26.4–27.5 ms/帧（37 fps，GPU 忙 90–93%，填充率上限）；
App 内 GPU 14 ms/帧，瓶颈在 CPU 调度与串行链 → 优化后 50–60 fps。**桌面到不了 iPhone 的 60fps**。

## 5. 这轮踩过的坑（别再踩）

1. **不要追"启动前几秒"的日志**：一次性日志半秒内滚走，视频/照片几乎抓不到。
   **默认做成常驻**（每 10 秒重复），这是本轮最大的效率教训。
2. **推 CI 前必须本地检查补丁**：hunk 行数错 / BOM 混入 / 把函数插到 `static void` 和函数名之间 / `getPlatform()` 未转换 / `strlcpy` 在 IOKit 环境没有声明 —— 这些都白烧过整整一次构建。
3. **0176 的 SweetHID 触发路径在真机上没执行**（330 的日志里没有 `SWEET GPU`），所以改成由 `sweet_mali_power()` 主动调用；两条路都留着但用 `gSweetGPUStarted` 去重。
4. **本地 `payload/out/worktree` 是旧快照**，不能代表 CI 的最终树；`tools/replay_patches.py` 对它重放会大量失败，别据此下结论。
5. **视频抽帧用 `tools/vidscan.py`**（顺序解码）；`vidframe.py` 的 seek 在长 GOP 4K 视频上会返回同一帧。
6. 镜像打包/刷机时机：只写 `boot_a`，电池 ≥3900mV，`current-slot` 必须是 `a`。

## 8. 下周待办：本地 Linux 构建 XNU（不再等 CI）

**动机**：CI 每次 5–6 分钟，失败要等 6 分钟才知道。目标改成本地增量编译 1–2 分钟。

**方案**：参考 `oosexgang/hakios-xnu-kernel`（mtk 分支）的 `xnu-build.sh` + `xnu-deps/setup.sh`
（首行注释即 "Build XNU for redwood on Linux"），用 theos 的 Linux 版 cctools（ld64）+
iPhoneOS 16.5 SDK + hostinc 兼容层 + `gen-iig-stubs.py`，在 Linux 上直接编 Darwin arm64 内核。

**磁盘需求（C 盘）**：

| 项 | 大小 |
|---|---|
| theos Linux 工具链 | 1.5–2 GB |
| iPhoneOS 16.5 SDK | 3–5 GB |
| XNU 源码 + 270 个补丁 | 2–3 GB |
| BUILD/obj 构建产物 | 8–10 GB |
| apt 依赖 | 2–3 GB |
| **合计（建议预留）** | **30–35 GB** |

（当前 C 盘可用 55.1 GB，够；以后要编 Mesa 再另加 10–15 GB。**不要放 D 盘**——
D 是机械硬盘，实测顺序写 48 MB/s。）

**步骤**：

1. 在 C 盘新建精简 WSL Ubuntu（别迁现有的 30 GB 旧环境，干净一些）
2. apt：clang/llvm、bison、flex、make、python3、autoconf、automake、libssl-dev 等；
   用发行版 LLVM，**不要从源码编 LLVM**
3. 装 theos + Linux 工具链 + iPhoneOS 16.5 SDK
4. 取 xnu-8796.121.2 源码，按序打 `xnu/patches/` 全部补丁
5. 板级配置用我们的 CAMELLIA（补丁里已含 `config/MASTER.arm64.camellia`、`MakeInc.def`）
6. 首次完整编译验证 → 之后用增量 `make`
7. 产物 `kernel.development.camellia` 交给 `tools/mk_device_boot.py` 打 boot.img

**验收**：改一行内核代码 → 本地 2 分钟内出可刷镜像；与 CI 产物功能一致（都含关键日志字符串）。
